**Claude Code**（デスクトップアプリ、VS Code 拡張機能、ターミナル）または **Cursor** の中で、あなた自身のコンピューター上で動きます。有料サービスは必要ありません。ナレーションを付けたい場合に限り、あなた自身の Gemini キー（無料枠あり）、ElevenLabs、または無料のトルコ語音声を使います。

## 作れるもの

### コードで作る短編映画

思いついたことを一文で伝えるだけ。あとは一緒に形にしていきます。

- **ありきたりで終わりません。** エージェントはあなたのアイデアを、世界からランダムに引いた実在のもの（博物館の所蔵品、動物、宇宙から撮られた写真、昔の発明、史跡、伝統工芸）と掛け合わせます。だから届くのは誰もが最初に思いつく映画ではなく、あなた自身も考えなかった解釈です。
- **同じことを繰り返しません。** どの提案も、あなたがこれまでに作った映画と照らし合わせるので、同じ映画を二度出すことはありません。
- **最後に決めるのはあなたです。** 映画を何で作るかを選べます：本物の光の 3D、2D アニメーション、絵の具、インク、紙、粘土、モーショングラフィックス、ピクセル。実在の映画のスチルを並べたボードからルックを選び、映画全体を作る前に最初の 2 シーンを見て承認します。

### YouTube 向けの長尺動画

10 分以上のドキュメンタリー、解説動画、ビデオエッセイを、フィルムモードで幕と章に分けて制作します。

- リサーチに基づいた脚本。実在の人物や出来事に関するすべての主張に出典が付きます。
- 最初の 1 分で投げかける未解決の問いと、視聴者を最後まで引きつける好奇心マップ。
- あなたの言語によるナレーション（トルコ語と英語の音声。無料のトルコ語音声も含む）。エンジンの素の声のままではなく、その映画ならではの音声処理を施します。
- オープンなアーカイブから集めた記録写真、地図、文書、映像。そして写真が存在しない部分はコードで表現します。自ら描かれていく地図、カウンター、図解、再現された場所。
- 形式に合う場合はチャプターカード、幕ごとに耳で選んだ音楽、−14 LUFS のマスタリング、動画の説明欄に使えるクレジットファイル。

### 広告・製品映像

あなたの製品、カラー、フォント、ロゴ、コールトゥアクション。製品は細部まで作り込まれ、スタジオ撮影のようにライティングされます。ソフトウェアには UI ヒーローショットを用意します。固有性テストによって、ほかのどのブランドにも当てはまってしまう映像になるのを防ぎます。9:16、1:1、16:9 の各バージョンがセーフエリア付きで揃います。

### SNS 向けの解説動画

30〜60 秒の縦型動画。最初の 1 秒で問いを投げかけ、トルコ語の表示を確認済みのオープンなフォントの組み合わせによるキネティックタイポグラフィ、一行ずつ組み上がっていく図解、スマートフォンの画面サイズでも読める文字。

### ミュージックビデオ

あなたの曲を持ってきてください。ビートグリッドを計測し、カットを小節に、ヒットを拍に合わせ、歌詞の一行ごとに一つの映像を当てます。

### その他

- **好きな動画のように、でも別物に：** その動画の形式（カット、テンポ、光、色）を計測し、その形式の上に新しい映画を作ります。元のフレームは一切使いません。
- **あなた自身の映像の編集：** トーキングヘッドや画面録画を、単語単位でタイミングの付いた文字起こしからカットし、間を詰め、グラフィックを言葉に合わせます。
- **同じフォーマットでシリーズを：** ある映画のフォーマットを保存し、次のエピソードをそのフォーマットで作ります。

15 秒のクリップから 10 分以上の作品まで。クイックモードでは 1 回のセッションで最長約 3 分の映画を作れます。フィルムモードでは、承認を重ねるステップを通して長めの映画を仕上げます。映画が長くなるほど、時間と使用量も増えます。

## 仕組み

1. **アイデアを伝えます。** 一文で十分です。完全なブリーフがあれば、すぐに作業に入ります。
2. **いくつか質問します**（アイデアの解釈、映画の素材、長さとフォーマット、ルック、サウンドと音楽）。それぞれに ★ 印の推奨回答が付いています。
3. **プランを見せます。** テキストで、秒単位のビートと、一行ずつ変更できるディレクターカードを提示します。続いて、残りを作る前に 2 つのシーンをスチルで見せます。
4. **ドラフトをレンダリングし、** チェック（最初のフレームからの動き、ラウドネス、可読性、繰り返し）を行ってからあなたに見せます。さらに、独立した視聴者が予備知識なしで見ます。あなたのメモは、それが関わる部分だけを変更します。
5. **完成版：** フルサイズで −14 LUFS にマスタリングし、動画の説明欄に使えるクレジットを添えます。

## 2 つのモード

エージェントは最初にこれを尋ね、あなたの目的に合ったほうを勧めます。

| | **クイックモード** | **フィルムモード** |
|---|---|---|
| 一言で | 映画全体を 1 ファイルで、少しの質問、低解像度のドラフト、1〜2 回の修正 | まずロードマップと脚本全体を承認。その後、あなたの OK を得ながら段階ごとに制作するか、ドラフトまで一気に進む。リサーチ、レイヤー構成のサウンド |
| 向いているもの | 約 1 分未満のものなら何でも（ブランドやクライアント向けの作品も含む）。SNS 用クリップ、解説動画、広告、約 3 分までの作品。短編映画の最初のドラフトを数分で。承認は約 3 回 | 複数のシーン、リサーチやアーカイブ素材を含む長めの映画：ドキュメンタリー、ナレーション付きの作品、映画祭向けの短編。段階ごとなら承認は約 6〜8 回、一気に進めるなら約 3 回 |
| 進め方 | いくつかの質問（素材、ボイスオーバー、音楽、リファレンスを含む）→ 任意のリサーチ（あなたの作品に似たルックの映画のスチル、題材が実在する場合は実物の形）→ テキストでのプラン（ビート、ディレクターカード、リファレンスボード）→ 2 つのシーンをスチルで確認して OK、その後に残り → 低解像度ドラフト → ドラフト上で最大 2 回の修正 → 最終レンダリング | 6 つの質問 → ロードマップ → 脚本 → スタイルフレーム → アニマティック → レンダリング。段階ごとにあなたの OK を得るか、脚本からドラフトまで一気に |
| 映像 | 自己完結した 1 つの `film.html`：時間の関数としてのシーン、Canvas 2D または three.js / WebGL、画面上のテキスト | 8 つのルックプリセットを持つ three.js のシーン、ショットごとのレンダリング |
| サウンド | バージョン 1 から同じファイル内でデザイン（Web Audio、オフラインでレンダリング）：シーンごとの環境音ベッド、映像のキュー表に沿った効果音、共有の 1 つのリバーブ、アレンジ表に基づく音楽 | レイヤー構成のベッド、フォーリー、見せ場、声、音楽を備えた、デザインされたサウンドアイデンティティ |
| エージェント | 1 つのメインチャットが制作・レンダリング・修正を担当（高速）。リサーチはバックグラウンドで行い、ヘルパーは予測テスト、重複チェック、ナレーションのテイク、各ドラフトの独立した視聴者にだけ使う | メインチャットは手元にあるものを制作。ヘルパーは独立した部分（サウンド、ナレーション、リサーチ、レビュー）や長尺映画の各章を並行して担当 |

クイックモードで始めて、あとからフィルムモードに移すこともできます。その場合、ビートがロードマップになります。

## 2 つの目的

モードと一緒に尋ねます。モードは作業をどこまで深く行うかを決め、目的はどんな種類の映画かを決めます。その後のすべて（質問の初期値、リファレンス、チェックポイント、チェック）は目的に従います。

| | **シネマティックな映画** | **広告・製品**（ブランド、ローンチ、プロモーション、解説） |
|---|---|---|
| 狙い | レンダリングではなく撮影したように見える、物語・ムード・アート作品 | 一つの題材のためだけの映画。誰のものか、次に何をすべきかを伝える |
| 映像 | シネマティックパス：浅い被写界深度とレンズの個性、粒子感、カメラオペレーターの慣性。リクエストに応じて（初期設定ではオフ）速い動きへの 180° モーションブラー、キット独自のプリントカーブによるフィルムトーン、ゲートウィーブ。カメラワークはショットごとに選択 | 固有性テストと競合テスト、ロワーサードとしての画面上の名前、ソフトウェアには UI ヒーローショット、あなたのブランドカラーとフォント（オープンフォントは Fontsource から。あなた独自のブランドフォントはローカルに留まります）、コールトゥアクション付きのエンドカード |
| サウンド | 環境音主体、シグネチャーサウンド、音楽はあなたの選択 | 初期設定はナレーター + 音楽 |
| 納品 | あなたが選んだフォーマット | セーフエリア付きの 9:16、1:1、16:9 の各バリエーション |
| 追加 | — | 任意：あなた自身の映像や画面録画を、単語単位でタイミングの付いた文字起こしからカット（Whisper が必要）：間の短縮、あなたが承認する言いよどみや撮り直しのフラグ、言葉に合わせたグラフィック |

詳細：`references/purpose-cinematic.md`、`references/purpose-ad.md`、`references/footage-edit.md`。モーション、カメラの語彙、フォント、サウンドの同期、フック、1 ショット 1 アクション、各種チェックは両方に共通です。

## 含まれるもの

- **脚本執筆システム：** 気の利いた、短く、的を射た脚本のため（両モード共通）。発散してから収束、物語に転換点があれば明確に、結末から考える、語らずに見せる、ワード数の予算、英語とトルコ語の禁止クリシェリスト、音読と 30% 削減のパス、初見の視聴者チェック。
- **名前の付いたカメラワークとトランジションの語彙**（`references/camera-moves.md`）：カメラの動き、フォーカスの動き、トランジション（ドリーイン、オービット、ドリーズーム、FPV、手持ち、スピードランプ、ラックフォーカス、マッチカット、ウィップパン、J カット…）と、それぞれが視聴者に与える感覚、標準の長さ、速度、イージング。各ショットのカメラは一行で書けます：*「ドリーイン、3 秒、ゆっくりした ease-in-out、人物に向かって」*。どちらのエンジンも、これらを時間の純粋関数として実装しています（`film.html` の 2.5D カメラ、three.js 用の `starter/camera.mjs`）。
- **クイックモードのスターター：** `film.html`。決定論的なタイムライン、奥行きのあるレイヤーを持つ 2.5D カメラ、トランジション、映像とサウンドで共有するキュー表、シード付き乱数（シード付きデータ用の遅延キャッシュ付き）、ダイアクリティカルマークに合わせたサイズのテキストヘルパーと名前ラベル、そして小さな Web Audio の音色（パッド、キック、ティック、ヒット、ライザー、ウーッシュ、プラック、柔らかいリード、フォーリー、環境音ベッド、共有の生成リバーブ）と、毎回のレンダリング前にチェックされるアレンジ表。ブラウザーでクリックすると、映像とサウンドが一緒に再生されます。
- **フィルムモードのインタビュー：** 3 回の短いラウンドで 6 つの質問（ラウンドの合間にディレクションボードを提示）。そして **8 つのルックプリセット**（シネマティックリアル、アニメ／セル、パステル絵本、クレイアニメ、切り絵／コラージュ、レトロ／シンセウェーブ／VHS、光沢のある CM 調、手描きインク）に加え、あなた自身のリファレンス画像からカスタムルックを作る方法もあります。同じ 8 つの系統はクイックモードでも使えます（グレーディング、テクスチャー、トゥーンシェーディング、2 コマ打ちの作画）。
- **映画にふさわしい声：** ナレーションをエンジンの素の声のまま出すことはありません。映画ごとに、声の聞こえ方（近い、テープ、ラジオ、コーラス、水中、機械…）と、声が置かれる場所（部屋、ホール、石造りの身廊、屋外）を選び、映画のシグネチャーサウンドを声の中に織り込むこともできます。どのセリフも同じダイアログレベルに揃います。
- **この動画のように、でも…：** 好きな動画を `refs/` に入れて、何を変えたいかを伝えてください。形式（カットとショットの長さ、テンポ、パレットと光、BPM、カットが拍にどう乗るか）を計測し、変えたいところを変えて、その形式の上に新しい映画を作ります。元のフレームや音楽は一切使いません。
- **あなた自身の曲：** 曲やトラックを持ってくれば、映画はそのビートグリッドに従います。テンポは曲全体で計測し、クリップは小節線で切り出し、カットとヒットを小節と拍に合わせ、歌詞の一行ごとに一つの映像を当てます。ナレーションの下では音楽が自動的にダッキングします。
- **ディレクションボード（フィルムモード）：** アイデアを伝えると、3 つのビジュアルの方向性を 1 枚の画像で提示します。それぞれがスタイルと、そのルックを体現する実在の映画 2〜3 本のスチル（FilmGrab、ムード参考のみ）、計測したパレットで構成されます。選んだものは映画の光と色に落とし込まれ、スタイルフレームはそれと照合されます。
- **アイデアごとに見つけるルック：** 実在の映画から得た方向性（映画のスチル、撮影監督や写真家。ムード参考のみ）と、語彙としてのスタイルレシピの棚（木版画、浮世絵、影絵、リソグラフ、サイレント映画など。大半は LemoLab によるもの。クレジットを参照）。読み込むのは選んだものだけです。
- **デザイナー水準のタイポグラフィ**（`references/typography.md`）：独立系のオープンなファウンドリーと Fontsource による、ライセンス上問題がなくトルコ語の表示を確認済みのフォントと組み合わせ。映画ごとに 3 つの組み合わせを引き、その映画自身のルックで見本カードとして提示します。Fonts In Use、Art of the Title、Typewolf、Are.na、そしてあなた自身のスクリーンショット（Instagram の保存も含む）を `refs/type/` に入れれば、タイポグラフィのリファレンスとして計測し、書体の方向性に落とし込みます。作品をまたいであなたの選択を学ぶテイストログ。スマートフォンサイズでの可読性、コントラスト、ダイアクリティカルマークのチェック。任意で、単語単位で同期したトーキングヘッド用キャプション。
- **サウンドデザインの基本：** 映画ごとの軽いサウンドアイデンティティ、レイヤー構成のベッド、検証済みの ffmpeg レシピ、−14 LUFS のマスタリング。
- **依存関係のない小さなツール群：** フレームキャプチャー（MP4 への直接出力や、ページのサウンドトラックの WAV 書き出しにも対応）、アニマティックビルダー、ミキサー、マスタリング、品質チェック（計測によるフックチェック、カメラの動きを除いたシーンごとの被写体の動き、シーンごとのラウドネスと耳障りさを含む）、ライセンスログ付きのオープンライセンス素材検索。

## 動作要件

- ローカルのツールを実行できる AI コーディングエージェント：**Claude Code**（デスクトップアプリ、VS Code 拡張機能、またはターミナル）または **Cursor**。claude.ai の通常のチャットではあなたのコンピューター上でツールを実行できませんが、Claude Code ならできます（ffmpeg、Chrome、各スクリプト）。
- Node.js 22+、Python 3.9+、ffmpeg、Google Chrome（または Chromium / Edge）。足りないものは、あなたの OK を得てからエージェントがインストールします。それ以外は不要で、Windows でも同じです。キットは Claude Code 自身の PowerShell で動き、bash は使いません。Git はキットのインストールと更新にだけ使い、レンダリングには使いません。Claude Code のセッションでキットのガードが動かない場合、映画のセットアップに GUARD OFF と表示されます（テストはプッシュのたびに Windows と Linux で、変更のたびに事前に macOS で実行しています。Windows で映画を丸ごと 1 本作る検証はまだ行っていません）。フックには新しめの Claude Code（exec 形式のフックと `onFailure`、2.1.295 以降）が必要です。古いクライアントではガードが登録されないことがありますが、映画の制作自体は進みます。
- Chrome が使える GPU（最近の Mac なら何でも、または正常に動作するグラフィックドライバーを備えた PC）。
- ディスク容量：クイックモードはフレームを直接 MP4 に流し込むので、数百 MB あれば十分です。フィルムモードはレンダリング中に映画 1 本あたり数 GB が必要です。

どれかが足りませんか？そのまま始めてください。エージェントがまずマシンをチェックし、足りないもののインストールを提案します（何かをインストールする前には必ず確認します）。それ以外には何もインストールしません。スクリプトは標準機能だけを使い、three.js はバージョンを固定したライブラリを CDN から読み込みます。

**無料のトルコ語音声（必要な場合）**（キットはどれもインストールしません。それ以外の場合、ナレーションにはあなたのキーによる Gemini TTS、または代用としてシステム音声を使います）：
- Canberk Aslan による [EMA Lightning](https://huggingface.co/canberkkkkkk/ema-lightning)（Apache 2.0）：クリアな 1 つの声、CPU でオフライン動作、PyTorch 込みで約 800 MB。インストールすればキットから使えます：`python3 tools/tts.py --install ema` を実行し、その後 `--engine ema`。
- [VoxCPM2 Türkçe ses tasarımı](https://github.com/alexturkey/voxcpm2-turkce-ses-tasarimi)（Apache 2.0）：説明文から声をデザインでき、すぐに使える 7 人のナレーター（ドキュメンタリー向けの声、低い声の語り手、ニュースキャスター）付き。Apple Silicon または NVIDIA のグラフィックカード、約 3.7 GB。
- Özgür Güler による [Ahenk](https://github.com/ozguradmin/ahenk-turkish-tts)：疑問のイントネーション、感情、笑い（大型モデル、NVIDIA のグラフィックカード）と、Ahenk Cep（小型、CPU）。重みは CC BY 4.0 なので、これを使った映画には Ahenk のクレジットを記載します。

## インストール

Claude Code（デスクトップアプリの **Code** タブ、VS Code 拡張機能、またはターミナル）を開き、こう伝えてください：

> https://github.com/sarpstar/cinecode から cinecode スキルをインストールして

エージェントは git を使って GitHub からキットを `~/.claude/skills/cinecode`（Windows：`%USERPROFILE%\.claude\skills\cinecode`）に取得します。git のない Windows コンピューターでは、あなたの OK を得てから先に git をインストールします（`winget install --id Git.Git -e`）。その後、新しいチャットを開いてください。あとで **「cinecode を更新して」** と言えば最新版になります。エージェントが 2 つのコピーを認識しないよう、インストール先は 1 か所だけにしてください。

手動で行う場合は、次の 1 行で同じことができます：

```bash
git clone https://github.com/sarpstar/cinecode.git ~/.claude/skills/cinecode
```

このスキルは、映画・アニメーション・広告に関する日常的なフレーズで起動します（"kısa film"、"animasyon"、"reklam filmi"、"ürün videosu"、"tanıtım videosu"、"make a short film"、"product video"、"ad"）。

### 1. Claude デスクトップアプリ（Code）

Claude デスクトップアプリを開いて **Code** に切り替え、映画用の空のフォルダーを選び、**「短編映画を作りたい」**（トルコ語：**"Kısa film yapmak istiyorum"**）と入力します。

### 2. VS Code 拡張機能（Claude Code）

Claude Code 拡張機能をインストールし、空のフォルダーを開いて Claude Code パネルを開き、同じ文を入力します。

### 3. ターミナル

```bash
mkdir my-film && cd my-film && claude
```

そして同じ文を入力します。

### 4. Cursor

Cursor の Agent チャットで、同じインストールを `~/.cursor/skills/cinecode` に行うよう頼むか、次を実行します：

```bash
git clone https://github.com/sarpstar/cinecode.git ~/.cursor/skills/cinecode
```

Cursor で空のフォルダーを開き、Agent チャットを開いて同じ文を入力します。キット独自のチェック（`make.py`、`qc.py`）は同じように動きます。一方、いくつかのミス（見せる前に脚本について尋ねる、ドラフトを見せない、承認の直後に止まる）をその場で止めるガードフックは、Claude Code でのみ動作します。

## クイックスタート

1. エージェントで空のフォルダーを開きます（インストールを参照）。
2. アイデアを書きます。必要なのはアイデアだけです。よくわからない項目は省いてかまいません。エージェントが尋ねます：

   ```text
   cinecode で映画を作りましょう：<何についての映画か、一文か二文で>。

   （わかっていれば書き添えてください。省いた場合はキットが尋ねます：）
   長さ：<15 秒 / 1 分 / 5 分…>
   公開する場所：<Instagram の縦型 / YouTube の横型…>
   サウンド：<ナレーター付き / 声なし / 自分の曲：ファイル>
   ルック：<思い浮かべている映画、写真、画家、または「おすすめを提案して」>
   ```

   モードは書かなくてかまいません。エージェントが作業の規模から提案します。書く内容が少ないほど質問が増えます。完全なブリーフ（ビート、言葉、長さ、フォーマット）があれば、質問なしでそのままドラフトに進みます。
3. モードと目的（シネマティックな映画、または広告・製品）を選び、1〜2 回の短いラウンドで質問に答えます（推奨の選択肢には ★ 印が付いています）。
4. 各チェックポイントで承認するか変更します。完成した映画は、映画フォルダーの最上位に `<title>.mp4` として置かれます。

## クイックモードの流れ

| # | ステップ | あなたがすること |
|---|---|---|
| 1 | **いくつかの質問：** アイデア、素材（映画を何で作るか）、長さとフォーマット、スタイルとムード、サウンド（ナレーター + 音楽、音楽と効果音のみ、または画面上のテキスト + 音楽。ナレーター付きなら声のタイプと言語も）、音楽そのもの（耳で選ぶ実際の録音、あなた自身のトラック、コードで書いたもの、またはなし）、リファレンス（検索する、自分のものだけ、またはスキップ）。サウンドアイデンティティは一行で提案されます | 答える、または「OK」 |
| 1b | **軽いリサーチ（選んだ場合）：** 題材の主要な要素についてのオープンライセンスのリファレンス。映画が長いほど多くなります（15〜30 秒なら 2〜3 件、60 秒なら 3〜5 件、それ以上は章ごとに 2 件。加えてあなたの `refs/`） | — |
| 2 | **プラン（テキストでのチェックポイント 1 回）：** ログライン、転換点、カメラ指示付きの秒単位のビート表（一つの流れで、長めの映画では内部の章ごとにまとめる）、テキストやセリフ。リサーチを行った場合はリファレンスボード。一行ずつ変更できる短いディレクターカード（ルック、カメラ、モーション、テンポ、トランジション、書体、サウンド、仕上げ） | OK、リファレンスの差し替え、メモを 1 つ、またはリファレンスの追加を依頼 |
| 3 | **まず 2 つのシーン：** 残りを作る前に、ルックと 2 つのシーン（オープニングと、それと最も違うシーン）をスチルで | 先へ進む、またはメモを 1 つ |
| 4 | **制作とドラフト：** 映像とサウンドを収めた 1 つの `film.html`。仕上げエフェクトなしのハーフサイズのドラフト、−14 LUFS でマスタリング、フックをチェック | 見てから OK またはメモ |
| 5 | **ドラフト上での修正：** 的を絞った修正を最大 2 ラウンド。各ラウンドは新しいドラフトとして提示 | メモをまとめて送る |
| 6 | **最終レンダリング：** フルサイズで、オンにした仕上げエフェクト（モーションブラー、プリントトーン、ゲートウィーブ。すべて初期設定ではオフ）を適用し、再度チェック | 見る |

## フィルムモードの 6 ステップ

| # | ステップ | あなたがすること |
|---|---|---|
| 1 | **インタビュー：** 3 回の短いラウンドで 6 つの質問、合間にディレクションボード | 答える、または ★ の選択肢を選ぶ |
| 2 | **ロードマップ：** コンセプト、タイミング付きのショット（長さに応じた数：30 秒なら 4〜8、長めの映画では章と幕にまとめる）、ルック、サウンドアイデンティティ、フック、リスク | 承認する、または行を変更 |
| 3 | **脚本とテキスト：** 切り口、転換点、セリフ（またはセリフなし）、画面上のテキスト。脚本全体を一度に提示 | 承認または変更。制作の進め方を選ぶ：段階ごとか、ドラフトまで一気に |
| 4 | **スタイルフレーム：** 最終品質の 1 枚のスチル。以降のすべてのフレームの基準になります | 承認する、またはメモを伝える |
| 5 | **アニマティック：** 仮のサウンド付きの、タイミングを合わせた低解像度の動画 | テンポは合っているか？ |
| 6 | **レンダリング、サウンド、完成版：** まずミックス済みのサウンドを付けたハーフサイズのドラフト、続いてフルサイズの映像、マスタリング、チェック、納品 | 見て、メモをまとめて送る |

メモは、それが関わるショット、セリフ、サウンドレイヤーにだけ適用されます。各ラウンドは新しいバージョンになります。完成版を承認すると、エージェントはドラフトや中間ファイルを削除するかどうかを尋ねます。納品した映画、あなたのリファレンス、素材、音源、メモは常に残ります。

**組み込みのルール（両モード共通）：** 最初の 2 秒はフレーム 1 から動きます（計測済み）。すべてのフレームは時間の純粋関数です（再レンダリングしても同一）。外部ファイルはダウンロード時にすべてライセンスの行が記録されます。長いレンダリングはステータスファイル付きでバックグラウンド実行されます。エージェントはフルサイズのフレームではなく小さなコンタクトシートを見るので、コストを抑えられます。

**誰が作業するか（フィルムモード）：** メインチャットは、すでにコンテキストを持っているものを制作します。プロジェクトファイルからブリーフィングを受け、使用モデルを指定された新しいヘルパーエージェントが、並行して進められる独立した部分（サウンド、ナレーションのテイク、リサーチ、独立した視聴者）や、長尺映画の一つの章を担当します。あなたのメモは `notes/round-N.md` に原文のまま保存され、それが関わるショットだけが作業対象になります。不具合は、何かを作り直す前に数枚のテストフレームで診断します。チェックポイントでは、エージェントが新しいチャットを提案することがあります。Claude デスクトップアプリでは、あなたが「はい」と答えると自動で開きます。それ以外の環境では、新しいチャットを自分で開き、**「STATE.md から続けて」**（トルコ語：**"STATE.md'den devam et"**）の一行を貼り付けてください。詳細：`references/context-protocol.md`。チャットの各ステップはチャット全体を読み直すため、映画を安く仕上げる鍵はチャットを短く保つことです。各ヘルパーはそのタスクに必要なモデルで始め（センスや判断はあなたのチャットのモデルで、ファイル作業や素材集めはより軽いモデルで）、レンダリングは 4 行で応答し（`tools/make.py`）、画像は小さく保ちます。Claude Code では、キットのガードを起動する 3 つのフックによってスキルがこれを徹底します。チェック項目には次のようなものがあります：チャットが大きくなったときのリマインダー、チャット内に大きな画像を置かない、ヘルパーごとに 25 ステップの上限、ユーザーがまだ見ていないものについては尋ねない、キーファイルは閉じたままにする。

## よくある質問

**コードだけ？それともハイブリッド？** 中心はコードです。映像はコードで作られ、モデルのコストはかかりません。映画が長く、事実に基づくものであるほど、コードでは実物を見せられない部分に実際の素材が加わります。エージェント自身がオープンなアーカイブ（Wikimedia Commons、Internet Archive、NASA、博物館）で見つけた映像や写真、そして Pixabay のストック写真・動画（あなたの無料キーを使用。最初に一度だけ尋ねます）。いずれもライセンスとともに記録され、クレジットされます。サウンドについては、録音されたスコアと既製の効果音（無料の CC0 ライブラリー）をキットは推奨します。完全にシンセサイズしたサウンドも選べます。あなた自身の映像、写真、録音を加えることもできます。画像や動画の生成ツール（Higgsfield、fal など）を自分で接続した場合、エージェントはあなたが頼んだときに最後の手段としてのみ使い、自分から提案することはありません。顔は、様式化するか、クローズアップではシルエットにすると最もうまくいきます。

**映画ごとに API キーを入力する必要がありますか？** いいえ。ナレーションで初めてキーが必要になったときに一度入力するだけです。エージェントがテキストエディターでキーファイルを開き、空の `GEMINI_API_KEY=` 行を用意するので、`=` の後ろにキーを貼り付けて保存し、閉じてください（ターミナルなら `python3 tools/keys.py set GEMINI_API_KEY` で、入力内容を表示せずに入力できます）。以降の映画はすべてそのキーを使います。以前の映画の `.env` に入れたキーは、`keys.py import` でそこへ移せます。キーが映画フォルダーやリポジトリに入ることはありません。

**何ができるかはどうやって知ればいいですか？** 「何が作れる？」（"neler yapabilirsin?"）と尋ねてください。短いメニューが表示されます：短編映画、広告や製品動画、あなたの曲のミュージックビデオ、リファレンス動画のような映画、あなた自身の映像の編集、保存したフォーマットでの新作、スタイルを見て回る。あるいは、やりたいことをそのまま伝えてください（「この曲のミュージックビデオを作って」）。エージェントが適切なルートを選びます。

**どちらのモードを選べばいいですか？** 今日中に完成した映画が欲しい、あるいは頻繁に投稿するならクイックモード。一本の作品を可能な限り良いものにしたいならフィルムモード。エージェントがあなたの目的から勧めます。

**1 本の映画にどれくらい時間がかかりますか？** クイックモードでは、30 秒の映画は短い 1 セッションで済みます。いくつかの質問、1 つのプラン、確認する 2 つのシーン、素早いドラフト、そして最終レンダリング（それぞれ数秒から数分）。フィルムモードでは、30 秒の映画は通常数セッションかかります。インタビューとロードマップは数分、脚本とスタイルフレームは 1 回の作業で、30 秒の映画のレンダリングは最近の GPU なら数分です。時間の大部分はあなたのメモに費やされますが、それこそが肝心なところです。

**強力な GPU は必要ですか？** 最近の Mac（Apple silicon）か、正常に動作するグラフィックドライバーを備えた PC なら十分です。エージェントが最初にこれをチェックします（`capture.mjs --probe`）。ヘッドレス Chrome で GPU が使えない場合、レンダリングは CPU にフォールバックします。テストには問題ありませんが、映画を丸ごと 1 本作るには時間がかかります。

**自分のリファレンスを使えますか？** はい。画像を `refs/` に入れ、リンクやタイムスタンプ付きの映画タイトルを `refs/links.txt` に書いてください。著作権のあるリファレンスはムードの参考にだけ使い、フレームに使うことはありません。

**作った映画を商用利用できますか（広告、クライアントワーク、収益化したチャンネル）？** キットに関する限り、できます。キットが引く、あるいは見つけるフォントはすべて、画面上にも説明欄にも何も表記する必要のない商用利用可能なライセンス（SIL OFL、Apache、MIT、Ubuntu Font Licence、CC0）のものです。フォントは映像の中で使われるだけで、ファイルとして販売・共有されることはありません。厳選した 4 つの書体は Fontshare（ITF Free Font License）のもので、これも商用利用は無料ですが、自分でダウンロードする必要があり、ファイルを他人に渡してはいけません。キットはすべてのフォントファイルを git に含めません。エージェントが見つけたリファレンスはムードと形の参考にだけ使います。画像や音が映画に入るのは、それを許可するライセンスがある場合だけで、`LICENSES.csv` に記録されます。あなた自身のロゴ、ブランドフォント、映像、曲については、あなたの責任となります。オープンな音楽と画像について：キットが扱うのはパブリックドメイン、CC0、CC BY の素材と、画像に限り CC BY-SA の素材だけです（音楽は CC0 を優先）。それぞれのライセンスを記録し、すべての完成版の横に動画の説明欄用のクレジットを書き出します。公開前には各素材の出典ページを確認し、クレジットファイルは映画と一緒に保管してください（CC BY のトラックに対する YouTube の Content ID の申し立てへの回答になります）。映画のライセンスについては、それを公開する人が責任を負います。キットは現状のまま（MIT ライセンス）提供されます。これは法的助言ではありません。

**クレジットはどこに書けばいいですか？** 動画の説明欄（YouTube）や投稿のキャプション（Instagram、TikTok、X）に書いてください。映像の上には書きません。すべての完成版には、映画の横に `<title>-credits.txt` が残るので、それをそのまま貼り付けてください。パブリックドメインと CC0 の素材には表記は不要です（それでもファイルには簡潔に記載されます）。CC BY と CC BY-SA の素材には表記が必要で、ファイルにはすでにライセンスのリンクが含まれています。プラットフォームがトラックや画像を指摘してきた場合も、このファイルが回答になります。

**作った映画はどこに保存されますか？** エージェントを起動したフォルダーです。そこが空か、映画だけが入っている場合は、映画ごとにそこにサブフォルダーが作られます。そうでない場合（ホームフォルダー、デスクトップ、コードのプロジェクト）は、エージェントがそこに `Films` フォルダーを 1 つ作り、すべての映画をその中に保存します。パスはエージェントが伝えます。次回も同じ場所でエージェントを起動し「続けて」と言えば、映画が名前順に一覧表示されます。 フォルダーを選ばずに始めた場合（Claude アプリでフォルダーのないチャット）、映画はホームフォルダーの映画用フォルダーに保存され、エージェントがチャットをその映画のフォルダーに移します。これでスチル、音楽、ドラフトがチャットに表示されます。

**映画はどこにありますか？git は必要ですか？** 完成した映画は `<title>.mp4` として映画フォルダーにコピーされ、エージェントがそのパスを伝えます。必要なのはそのファイルだけです。git に触れる必要は一切ありません。git がインストールされていれば、エージェントは映画のテキストファイルのローカル履歴を残します（まずい編集を元に戻せるように）。どこにもアップロードされることはなく、動画は履歴に含まれません。

**気に入った映画がありました。次の作品を同じフォーマットにできますか？** はい。完成版のあとに「フォーマットを保存して」（"formatı kaydet"）と言い、次回は「同じフォーマットで」（"aynı formatta"）と言ってください。ルック、書体、サウンド、カメラのスタイル、リズムは維持され、尋ねられるのはアイデアだけで、シーンと言葉はそのアイデアのために新しく作られます。フォーマットはあなたのコンピューター上に保存されます（`~/.cinecode/formats`）。

**1 本の映画でどれくらいのトークンを使いますか？それはどうやって確認できますか？** 映画づくりは、エージェントがコードを書き、レンダリングし、チェックする長いチャットです。30〜60 秒のクイックモードの映画なら、通常 100〜250 ステップかかります。各ステップはチャット全体を読み直します。その大部分はキャッシュから読まれるので安価ですが、チャットが長くなるにつれて各ステップも大きくなります。そのため、あるステップが終わってチャットが大きくなっていれば、キットは新しいチャットで続けることを提案します。映画はファイルの中にあるので、何も失われません。映画フォルダーで `python3 tools/usage.py` を実行すると、チャットごとのトークン数が表示されます（Claude Code）。また、どのチャットも、インストール済みのすべてのスキルの短い説明と、接続済みのすべてのプラグインやコネクターのツール定義から始まります（スキルの完全な指示は使われるときにだけ読み込まれます）。その映画に不要なものをオフにすれば、すべてのステップが安くなります。

**対応言語は？** エージェントはあなたの言語で応答します。字幕は頼まない限りオフです（最大 2 言語、上下に重ねて表示）。

**オフラインで使えますか？** レンダリング、ミキシング、各種チェックはオフラインで動作し、クイックモードのスターター（Canvas 2D、Web Audio）も同様です。検索にはネットワークが必要です（リファレンス、音楽、初回のフォントとスタイルのダウンロード。これらはその後キャッシュされます）。three.js のシーンはライブラリーのために一度だけネットワークが必要です（またはローカルコピーを使用。`references/looks.md` §6 を参照）。`starter/index.html` は何も必要としません。

## テスト

キットのフォルダーで `python3 -m unittest discover -s tests` を実行してください。実際の Chrome と ffmpeg を使うテストを行うには、先頭に `CINECODE_BROWSER_TESTS=1` を付けます。テストスイートは、プッシュのたびに Windows（Git と bash がある場合とない場合の両方）と Ubuntu でも実行されます。何か問題があれば、GitHub で報告してください。
